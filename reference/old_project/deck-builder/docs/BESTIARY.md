# Bestiary

Generated by reading every `EnemyData` resource under `resources/enemies/`
directly, plus the `EncounterData` resources under `resources/encounters/`
that reference them, and the actual pool-selection code (`enemy_pool.gd`,
`encounter_pool.gd`, `room_state.gd`). Read-only export — nothing in the
project was changed to produce this.

**A structural note before the per-enemy detail:** exclusion from the
normal pool happens two different ways, not one. `EnemyPool.list_all()`
only scans `resources/enemies/` itself (`DirAccess.get_files()` doesn't
recurse), so `opening/`, `encounter_only/`, `bosses/`, and `retired/` are
excluded **by folder** — structurally, with no per-file flag to forget.
`Wardling`, by contrast, lives in the *same* top-level folder as
Glasswing/Beachwrack/Outbound and would be scanned like any of them —
it's excluded from ordinary rolls purely by `EnemyPool.pick_random()`'s
own `if enemy_data.is_elite and not allow_elite: continue` check, a
runtime flag filter, not a folder one. Both mechanisms produce "never
solo-rolled," but they're not the same guarantee - a bug in the flag
check could put Wardling back into ordinary rooms; a bug in folder
scanning couldn't, since `list_all()` never even looks at `opening/`
etc. unless explicitly told to.

## Groups

### Normal pool (solo-rollable) — 3
Glasswing, Beachwrack, Outbound. All three live in the top-level
`resources/enemies/` folder and are reachable through
`EnemyPool.pick_random(allow_elite=false, current_layer)`
(`room_state.gd`'s `_generate_combat_layout()`). Outbound is real but
back-loaded (see Q2).

### Elite — 1 dedicated (+1 shared)
Wardling is elite-exclusive (only reachable via `wardling_solo.tres`).
Glasswing is *also* elite content via Twin Glasswings, without being
elite-exclusive itself - it's a full member of the normal pool too (see
Q3). Both elite encounters are reached exclusively through
`EncounterPool.pick_random(ELITE_ENCOUNTER_FOLDER)`, never through
`EnemyPool` at all.

### Encounter-only — 3
Mushroom A, B, C. Structurally incapable of being solo-rolled - excluded
by folder, and mechanically meaningless alone (their `growth_start_stage`
stagger only makes sense authored together in `mushroom_patch.tres`).

### Opening room — 2 (folder), 1 actually used
Tideworn and Unrelieved both live in `resources/enemies/opening/`, but
only Tideworn is used by anything reachable in real play - and not for
"the opening room" any more (see Q3). Unrelieved is dormant (see
"unreachable" below).

### Boss — 1
BOSS_01. Loaded directly by `_generate_boss_layout()`'s own const
preload, never through any pool. Every run's boss fight is this same
enemy - there is no boss pool or variety today.

### Unreachable — 2
- **Thicket Stalker** (`retired/`) - excluded by folder placement, exactly
  like the other three exclusion folders mechanically, but with genuinely
  no live caller anywhere that would ever pass `include_retired` (that
  parameter doesn't exist on `EnemyPool.list_all()` at all). Confirmed
  dead content, not just visually retired.
- **Unrelieved** (`opening/`) - not excluded by folder in the same
  "structurally impossible" sense the other three are (its own file
  *would* be reachable if something called
  `OPENING_ROOM_INDUSTRIAL_ENEMY`), but nothing does. `RoomState.
  opening_room_variant` defaults to `COASTAL` and, per `room_state.gd`'s
  own comment, "never leaves COASTAL in real play" - no dev button or
  other code path currently flips it to `INDUSTRIAL`. Confirmed via
  reading the variable's own declaration and every reference to it: no
  writer exists besides its own default.

## Answers

### 1. How many distinct fights can a player actually encounter in one run today?

**8.** Tideworn (forced first real combat, exactly once per run), solo
Glasswing, solo Beachwrack, solo Outbound (layer 6+), Mushroom Patch,
Wardling, Twin Glasswings, and BOSS_01. Thicket Stalker and Unrelieved
are authored but contribute zero - they're not variety the player will
ever actually see. (Beachwrack's own debris-spawned second Tideworn is a
mid-fight variation on an existing Beachwrack encounter, not a ninth
distinct fight in its own right.)

### 2. Is anything in the pool but effectively never seen?

**Outbound**, functionally. It's real and reachable, but `min_layer=6`
locks it out of roughly the first half of an 11-layer run, and even once
eligible it rolls at `pool_weight=0.5` against Glasswing/Beachwrack's
1.0 each - a run that never generates a combat room at layer 6+ (possible
depending on how the graph branches that run) sees it zero times, and
even a run that does still sees it at noticeably reduced odds relative to
the other two options in the same room. Nothing else in the *reachable*
groups is meaningfully starved - Glasswing/Beachwrack are even odds
against each other in every eligible room, Mushroom Patch's 15%
encounter-chance is a real, non-trivial rate, and the elite 50/50 means
neither Wardling nor Twin Glasswings is rare.

### 3. Does any enemy appear in more than one group, or sit in a folder that contradicts its use?

**Yes, three things worth flagging:**

- **Glasswing** is a genuine dual-citizen: a full member of the normal
  pool (own file, own odds) *and* the entire enemy roster of the Twin
  Glasswings elite encounter (the same resource, referenced twice). Not
  a bug - `EncounterPool`'s own header comment describes this
  deliberately ("independently rollable AND reused twice") - but it does
  mean Glasswing is the only enemy whose difficulty tuning affects two
  completely different room types at once.
- **Tideworn's name no longer describes its folder - correction to this
  doc's own earlier claim.** An earlier version of this table said
  Tideworn lived in `resources/enemies/opening/`, folder-excluded from
  ordinary rolls the same way Unrelieved is. That was stale even at the
  time it was written: a 2026-08-29 pass ("Tideworn as a real
  encounter") had already moved it OUT to `resources/enemies/` itself
  (see `enemy_pool.gd`'s own comment on `OPENING_ROOM_ENEMY`), so it's
  actually been a normal, solo-rollable pool member (like Beachwrack)
  ever since - its exclusion from being the SECOND time you'd see it as
  the opening fight comes entirely from `room_state.gd`'s own
  `OPENING_ROOM_ENEMY` const forcing it as the run's first real combat
  specifically, a run-graph-position mechanism, not a folder one. This
  correction does not re-run the rest of this audit - the "Normal pool"
  group count, Q1's fight tally, and the "Opening room" group above all
  still reflect the OLD (folder-excluded) assumption and would need a
  fresh regeneration to account for this, not a hand-patch.
- **Wardling's `pool_weight=0.5` is authored but never read.** That
  field only ever matters inside `EnemyPool.pick_random()`'s own
  weighting, and Wardling is never selected through `EnemyPool` at
  all - only through `EncounterPool.pick_random(ELITE_ENCOUNTER_FOLDER)`,
  which weighs `wardling_solo.tres`'s own `pool_weight` (1.0, equal to
  Twin Glasswings) instead. The 0.5 on Wardling's own `EnemyData` is
  dead configuration - changing it would do nothing today.

One near-miss that is **not** actually a contradiction: BOSS_01 sets
`is_elite = true` despite never being reachable through the ELITE room
type. Per `enemy_data.gd`'s own doc, that flag also drives the
"gold-toned, larger" name-introduction treatment independent of pool
membership - BOSS_01 wants that visual treatment on its own merits, not
because it's pretending to be reachable as a normal elite.
